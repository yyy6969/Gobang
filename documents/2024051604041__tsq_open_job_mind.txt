1. 提炼降复杂度整合网络通信与联机对战

- 设计并实现基于 TCP/IP 的局域网通信协议，将易俊臣的 `game_server` 与 `game_client` 整合为统一的 `network` 类，降低代码维护成本。
- 实现局域网内玩家间的实时聊天消息转发机制，确保消息收发稳定。
- 修复联机对战中“重新开始”导致双方棋盘进度不同步的严重 Bug，通过信号机制强制重置对局状态。
- 因安卓 NFC API 功能受限且难以获取接口支持，主导技术方案转型，放弃 NFC 方案，保留接口，改用以 Wi-Fi 为基础的局域网直连方案。
- 实现设备本地 IP 地址的自动获取与 UI 展示，并允许其他玩家通过手动输入 IP 地址进行房间连接，手机端无法方便的获取到本机的ip地址，通过这一种方式直接获取到手机ip地址进行显示的操作，让对方能够直接知晓主机的ip地址，以便于进行输入或者加入房间的操作。

2. Android 端开发与发布适配

- 完成 Android 平台的编译环境搭建，选用 ARM 构建套件，成功打包并发布可运行的 APK 安装包。
- 适配不同分辨率安卓设备的显示大小，避免界面元素因屏幕比例差异而过度拉伸或压缩。
- 配置 `AndroidManifest.xml` 清单文件，尝试开启并集成 NFC 硬件功能，后因实际开发限制，知识储备不足，系统权限api申请可能不同及时调整方案策略，暂时搁置nfc的开发。
- 为安卓端定制应用图标及对应的 NFC 连接交互界面（UI 占位及跳转逻辑）。

3. 游戏核心交互与事件处理

- 优化“人人对战”下棋手感：实现悬停时显示拟落子阴影（视觉反馈），点击后二次确认才正式落子，提升操作确认感。
- 重构事件处理机制，采用 Handler 方式处理棋盘事件，修复游戏重新开始时棋盘数据残留、未及时刷新的显示问题。
- 修复 QML 前端与 C++ 后端交互中的 `Q_INVOKABLE` 访问权限问题，确保前端指令能正确触发后端逻辑。

4. 项目工程维护与轻量化

- 负责项目的初始代码库初始化（`first Init`）。
- 持续清理项目中的多余测试文件与冗余代码，更新项目目录结构及配置文件，保持工程整洁轻量，便于团队协作。

2： Android 端开发与发布适配
        ----
        a：首次移植进行开发，由于qt跨平台的原因，移植操作比较简单，直接通过切换配置环境就行，不过环境配置的问题会很大，由于grandle包在外网多次导致构建失败，通过下载离线包放置在环境路径当中，以便于grandle包的查看和运行操作，在android环境配置上进行了深刻的了解，一个合适的环境才适合用于合适的开发。

        b：关于nfc开发问题，目前推测是由于nfc在android 16的各个手机厂商的api权限问题不同，导致可能以往的低版本安卓系统不适配现在高版本的安卓系统，
        一些api或者头文件不兼容现有的安卓系统，或者我没有找到确切的可实现的api接口，但还是主要知识储备不足，进行尝试了，目前现有知识不支撑开发完整的nfc对战功能

        c：进行android开发，了解学习到android开发的一些流程和必要的配置文件，对安卓的一些软件有了更加深刻的学习，每个不同的操作系统开发出的软件都有其自身的开发路径

3. 游戏核心交互与事件处理
        a：以玩家的视角进行开发，优化游戏体验，不至于在下棋的时候点一下导致误触导致错误下子，以客户的视角进行开发才便于进行使用

        b：开发者视角了解到游戏运行的逻辑和渲染分离操作的重要性质，也就是前后端的不同开发职责，前端都是需要后端的数据支撑作为逻辑的渲染目标才能进行良好的交互体验，不然会导致联机对战的时候不同步的问题，不符合物理逻辑

4. 项目工程维护与轻量化
        a：重构带来的可以更加深刻的了解到原有的程序架构逻辑，解耦合的重要性，只有低耦合的程序才能更好的去维护，或者进行修改操作，才能更方便，不至于改了一处导致另外一处出现问题


总结-----此程序的开发了解到网络开发的一些流程，安卓开发配置调试的一些操作，以及知晓部分工程化思想的重要性质，知道一个程序是客户和开发者思维的集合，让开发更迅速和程序更好进行维护
